# BE201 1.1.20: native AWDL interface registration, DOWN only

Build pinned to Sequoia 24G824, BE201 8086:7740. Requires reboot; no runtime success claim.

The 1.1.19 hardware observation confirms one system create request: version 0, role 6, empty input BSD name. The handler still refused it. Native reverse engineering confirms role 6 uses createProxInterface; the generic controller factory only accepts role 7. The probe's radio MAC and the system's requested MAC differed.

New, default-off `be201_awdl_vif=1`: instantiate a concrete IO80211AWDLProtocol subclass, initialize with the system MAC, attach, initialize both registration views, create a bounded pool/four native queues, registerEthernetInterface, and return a name only if both a real BSD interface and its native name exist. No fabricated name or Link Up result. Failed registration/partial start is terminated and stopped before releasing queue and pool creation references. The native terminate prefix is also used before publication to close the init-time controller open, deregister PM interest and free native BPF resources. A protected, nonvirtual pointer-presence query detects partial native init without changing the base object's layout. The controller accessor remains valid before native start.

The controller serializes creation, rejects re-entry, waits for in-flight creation on stop and refuses publication after a stop request. Duplicate creates for the same address reuse the object; another address returns Busy. Native 24G824's generic VIRTUAL_IF_DELETE shim itself returns unsupported; this prototype owns one object until controller termination. All three extended-BSS fallback entry points now require the infrastructure-interface identity before their concrete cast.

Queue factory declarations use the exact exported Sequoia callback types (unsigned return; Packet *const * on submission). SDK variants differ, so only opaque factory declarations are used; no opaque queue is sized, constructed, virtually called or subclassed. Native queue/OSObject creation-reference release uses the SDK base prefix. The repository SDK itself is unchanged.

The interface remains DOWN; enable/running/link-up requests return unsupported. Known disabled synchronization queries return disabled. All remaining unimplemented typed requests return unsupported and record only a numerical handler index/count, without reading payloads, keys or passwords. Queue callbacks return zero packets and never fabricate a TX completion. No radio/probe context is enabled by the default candidate configuration, and no new data/TX path is connected yet. Capability bit 32 is experimental and only advertised with the explicit interface/probe switch; it does not claim an operational AWDL link.

Verification: all existing suites, actual concrete class 563-slot/63-handler native ABI/import validation, actual lifecycle allocation/failure/idempotent-cleanup schedules under ASan/UBSan, and actual controller factory duplicate/malformed/re-entry/stop-during-registration cases. Native framework internals and real thread scheduling are not emulated by host tests. Full build: 58 compilation units; 8 module constructors/destructors; all 1071 imports resolve in this host's kernel collection. SDK and API92/PNVM pins preserved. No Bluetooth, Music, account, identity or live NVRAM changes. Source remains uncommitted.

Acceptance for this stage: native awdl0 and IORegistry lifecycle counters after opening Finder AirDrop; record the next unsupported system request. AirDrop data, channel switching, synchronization/ranging and Watch lock-screen unlock are not accepted by this build.
