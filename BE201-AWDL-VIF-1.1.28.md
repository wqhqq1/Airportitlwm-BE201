This release adds a separately gated receive adapter. The Intel RX hook now runs after the existing FCS/MIC trailer and DMA-pad removal, before net80211. This addresses a concrete ordering error: the old observer was parsing the firmware trailer as TLVs. Whether that explains every one of the previous 802 parse-bad increments needs runtime confirmation. The hook uses the descriptor's actual receive channel and dBm signal, not the associated AP's inferred channel.

Unfragmented, unencrypted AWDL PSF/MIF frames with the AWDL BSSID, valid sender, version/OUI and bounded TLVs are eligible. The adapter fills a zero-initialized 72-byte apple80211_act_frm_hdr layout reconstructed from the installed Broadcom receive path and IO80211Family parser: sender at 0, channel at 0xc, receive clock at 0x28, RSSI at 0x2c. The Intel GP2 clock is passed as a raw microsecond device clock; no cross-device synchronization, AW schedule or ranging accuracy is claimed. Unknown rate and unused fields stay zero.

The native interface's getMgmtFramePool supplies buffers. getBuffer dispatch is slot 35 / 0x118 after OSObject's prefix, verified against native KC and the compiled fixture. The adapter checks capacity and exact write length, writes only the action body (no MAC header), and calls the exported nonvirtual bpfTapInput(buffer, 0xc, metadata, 0x48). Native actionFrameInput either consumes/returns the buffer or queues it and copies the 72 metadata bytes. Ownership transfers exactly once: failures before the call return the buffer, and no buffer access/return happens afterward. No new pool lifetime or native private-field mutation is introduced.

HAL resolves the owning controller, never retains a child pointer. The controller and interface check the shared workloop gate, creation/stop state and receive permission. The HAL also requires the requested monitor's active stage, no fault/shutdown/teardown. The interface retains itself around the native call to withstand reentrant teardown. Call count means submitted to the native entry, not accepted as a peer. ItlwmAwdlNativeRxSubmitted/Invalid/NoBuffer distinguish those stages.

debug.be201_awdl_vif_rx is RAM-only, defaults to zero and is registered/unregistered with the other six controls. The manual test enables RX plus the previous receive monitor, leaves synthetic host AW events off, and restarts only wifip2pd to request interface creation. There is no automatic sharingd/Finder restart, hotload, reboot or live Bluetooth modification.

Validation: 23 suites including actual lifecycle/ownership tests and ASan/UBSan on 300000 mutated RX frames, truncation and guard-page boundaries; 563 native dispatch slots, 63 typed handlers and the buffer-pool slot; 58 compilation units, native-import/entry/signature/SDK audits. Offline mocks do not emulate the native peer manager. Runtime acceptance and peer discovery are the next reboot experiment. TX, channel hopping, IPv6 data transport and ranging remain incomplete; no IFF_RUNNING or AirDrop/Watch success is advertised.
