# AirportItlwm 1.2.16：修复开机第一次发不出去；iPad 全时隙实验开关

跨信道隔空投送仍是开机默认启用（`be201_awdl_xchan=0` 关闭）。蓝牙驱动没有改动。

## 1.2.15 的结果（2026-11-14 09:11 开机）

- **默认启用生效了：** 开机后不用任何工具，ROC 就是模式 4（0x10024），第二信道在 149。
- **开机第一次发送失败：**
  - 09:13:17 开始连接；09:13:47 Bonjour 解析超时，报 NWError -65553（Refused），和 22:24 那次是同一个问题；
  - 连接期间，系统 AWDL 已经回到 Low Power，只有 2 个时隙在 149。
  - 原因：1.2.15 只在"已经有数据发往对方"或"对方时间表已展开"时才并入对方的时隙。解析阶段还没有单播数据，iPad 又从不展开时间表，所以 Mac 只在 149 待 2 个时隙。这是 1.2.15 引入的退步。
- **实验工具（09:15，发给 iPad）：**

  | 阶段 | 速度 | 149 时间占比 |
  |---|---|---|
  | 默认 | 0.01 MB/s | 43% |
  | 继续 | 0.10 MB/s | 53% |
  | 只留 1 个时隙给路由器 | 0.15 MB/s | 56% |
  | 收尾（64 秒） | 0.07 MB/s | |

  - 这次"最近单播目标"确实是 iPad（b1:3b:30），1.2.15 的修复起作用了；
  - 但 iPad 自己的时间表一直没展开：149 149 149 0 0 0 0 149 0 149 149 149 0 0 0 149，只有 8 个时隙在 149，第 8 个时隙也不去 2.4 GHz 的 6 信道；
  - ROC 期间收到 iPad 的帧只有 290–453（iPhone 约 1 万），等待超过 1 秒被丢弃的帧有 107 个。
  - iPad 连着 149 上的 Wi-Fi，它时间表里的"0"时隙很可能是在服务自己的路由器。它其实一直在 149 上，只是 AWDL 不保证这时候收。

## 改动

1. **"意图窗口"（60 秒）：** 只要系统时间表展开过（打开隔空投送面板、建立连接、传输时都会展开），或者有单播发出，之后 60 秒内，附近每台设备的 149 时隙都会并入。这样开机第一次发送时，解析阶段也能跟上对方。没有任何意图时，仍然只按系统本身的时间表走，平时不额外打扰路由器。
2. **驱动记录所有发送者的时间表**（最多 4 台，按最近使用替换）。
3. **实验开关 0x20000：** 正在收数据的设备，把它的空闲时隙也算成 149。用来验证 iPad 在这些时隙到底能不能收。
4. **实验工具 R2 三段：** 默认 60 秒、数据对端全部时隙 45 秒、默认（再次）45 秒，最后收尾到传完。

## 下次怎么看

- **开机后第一次直接发：** 应该能连上，不再等 30 秒后失败。
- **发给 iPad 的"数据对端全部时隙"那段：** 速度明显更高，就说明 iPad 在它的空闲时隙也能收，下一版可以对"连着 149 Wi-Fi 的设备"默认这样做；没有变化，就说明是 iPad 自己的限制。
