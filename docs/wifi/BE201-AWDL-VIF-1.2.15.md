# AirportItlwm 1.2.15：跨信道隔空投送开机默认启用；并集跟随所有有数据往来的设备

蓝牙驱动没有改动。

## 1.2.14 的实验结果（2026-11-14 08:55，`roc-20261114-085455.txt`，路由器在 36）

| 阶段 | 实际接收 | 速度 | 149 时间占比 | 路由器 |
|---|---|---|---|---|
| 默认 | iPad（单独发送） | 0.04 MB/s，最后失败 | 42% | 丢包 0% |
| 继续 | iPad，随后换成 iPhone | 0.20 MB/s | 52% | 丢包 0% |
| 留 2 个时隙给路由器 | iPhone | **2.28 MB/s** | 70% | 丢包 0%，平均 71 ms，最大 195 ms |
| 收尾 | iPhone | 30 秒内又传了 20.6 MB，随后停下 | | |

- 用户反馈：iPad 失败之后，再往 iPad 发就发不出去了；换成手机可以继续发。
- **关键发现：** 三段的"接收设备"都显示 iPhone（85:b5:1e），虽然这时只在往 iPad 发。
  - 驱动记的是"最后一个单播目标"。Mac 和 iPhone 之间一直有零星的后台单播（接力、连续互通之类），这个目标就被 iPhone 抢走了；
  - 结果 1.2.13 和 1.2.14 实际一直跟随 iPhone 的空闲时间表（149 149 149 0 0 0 0 0 6 149 149 0 …），没有跟上 iPad 展开后的时隙。
  - iPad 自己连着 149 上的 Wi-Fi，这可能是另一个次要因素，但主因是这个。

## 改动

1. **并集改为跟随所有活跃的数据对端：**
   - 驱动记录最多 4 台设备：最近 5 秒内有单播数据发往它的，或者它自己的时间表已经展开（至少 8 个 5 GHz 时隙）的；
   - 每台设备单独记它自己的时间表（2 秒内有效），并集取它们所有 149 时隙；
   - 没有任何活跃设备时，只按系统本身的时间表去 149，和原生 Mac 一样，也不再因为旁边设备的空闲时间表而离开路由器。
2. **跨信道隔空投送开机默认启用（`be201_awdl_xchan`，默认开，`=0` 关闭）：**
   - 开机后第二信道设为自动，ROC 设为模式 4（P2P_TXRX，值 0x10024）；
   - ROC 会等 link 1 上了第二信道之后才开始（和实验工具的顺序一样）；
   - 路由器在 2.4 GHz 时不会启用。以前在 2.4 GHz 的 6 信道上测出过 ping 553 ms 并断线；
   - 路由器本身就在 149（AWDL 的 5 GHz 信道）时，第二信道不会建立，ROC 也不会启用，因为根本不需要切换；
   - `开启/关闭跨信道隔空投送.command` 仍然可以在本次开机内手动开关。
3. **每段之间默认留 2 个时隙给路由器：** 速度和留 1 个差不多（2.28 对 2.22 MB/s），路由器延迟更低。开关 0x2000 改回只留 1 个。
4. **实验工具：**
   - 结束时把开关恢复成实验前的状态，也就是开机默认值，而不再全部关掉；
   - 输出里的"接收设备"改名为"最近单播目标"，另有"数据对端合并时间表"；
   - R2 为：默认 60 秒、继续 45 秒、只留 1 个时隙 45 秒，最后收尾到传完。

## 下次怎么看

- **重启后不运行任何工具，直接用隔空投送发给 iPhone 和 iPad，看能否传完。**
- **跑实验工具发给 iPad：**
  - "数据对端合并时间表"应该是展开的，大部分时隙在 149；
  - iPad 的速度应明显高于 0.04–0.2 MB/s。
- **平时上网：** 不传文件时，路由器的延迟应和关闭跨信道时接近。
