# AirportItlwm 1.2.27：撤回 1.2.26 的"回访路由器"

> **已撤回（2026-11-14 17:15）：** 最终的 Sequoia 版本退回 AirportItlwm 1.2.25。1.2.26–1.2.29 的代码保存在本地的 `git stash` 和 `outputs/archive/wifi-1.2.26-1.2.29-pause-experiments.patch`。

## 1.2.26 的结果（16:13 开机，路由器在 60）

- 16:14:44 开始发给 iPad，16:15:33 后进度停止，你在 16:16:00 取消。停止前传了约 365 MB，约 7 MB/s。
- 时间点完全对得上：
  - 暂停约在 16:14:32 进入（上传前的握手流量已经触发）；
  - 第一次"回访路由器"在进入后 60 秒，也就是约 16:15:32；
  - 进度在 16:15:33 停止。
- 之后发送队列卡住 4 次，**每次都还能听到 iPad**（对方无声 0 次）。0.5 秒重建也没恢复，4 秒没有数据后暂停结束（最长一次暂停 64.2 秒，正好对应）。
- 卡住期间 OwnFail 一直是 0：帧不是发送失败，而是根本没有被发出去。

**原因：** 回访时只把路由器的 PHY 调到 60 再调回来，而 AWDL 链路仍在这个 PHY 上、处于活动状态。之后固件就不再发送这条链路队列里的帧。正常的链路移动会先把链路停用，再换 PHY，再启用，所以没有问题；回访缺了这一步。这是我在 1.2.26 加的改动，适得其反。

## 改动

- 去掉回访（`IWX_AWDL_PAUSE_VISIT_US` 设为 0），恢复 1.2.25 的做法：单次暂停满 120 秒就正常退出，2 秒后如果仍在传输就重新进入。这条路径只用已经验证过的链路移动。
- 保留 1.2.26 的另外两项：暂停期间队列卡住后 0.5 秒重建，以及区分停顿原因的计数（`PauseHolds`、`PauseHoldsSilent`）。
