# AirportItlwm 1.2.25：暂停时沿用路由器的频宽，不再改速率控制

修正 1.2.24 暂停模式里会让固件崩溃的步骤。设计见 [BE201-AWDL-PAUSE-DESIGN.md](BE201-AWDL-PAUSE-DESIGN.md)。

## 1.2.24 的结果（2026-11-14 15:33 开机）

- **你看到的：** Wi-Fi 断开了，传输一直在等待。
- **驱动计数：**
  - 暂停进入 2 次、退出 0 次、放弃 1 次；
  - 丢弃路由器帧 293 个，忽略漏信标 84 次；
  - 固件出错 2 次（FwErrors 2），错误码 0x20101A27。
- **最后一条命令是 0x50F**（数据通路组的 TLC_MNG_CONFIG，即速率控制设置），返回超时（35），说明固件在这条命令上崩溃了。
- **结论：** 两次暂停都在进入时让固件崩溃，驱动重启固件、重新连接路由器，所以 Wi-Fi 断开，暂停也就没有真正生效，传输自然停在等待。

**原因：** 1.2.24 在调频前，把路由器站点的速率控制收窄到 20 MHz（`iwx_rs_init(update=false)`）。在已关联的链路上这样做，固件不接受。AWDL 对端的收窄以前在每次链路移动时都在做，没有出过问题。

## 改动

- **暂停期间沿用路由器自己的频宽：** 路由器的 PHY 调到 149 时，用和路由器相同的频宽（20/40/80 MHz），控制信道位置按 149 所在的频段计算（80 MHz 时为 149–161）。这样路由器站点和 AWDL 对端的速率控制都已经匹配（AWDL 对端在链路移回时已放宽到路由器的频宽），暂停全程不发任何速率控制命令。
- **路由器宽于 80 MHz 时**（例如 160 MHz），149 上没有对应的频段，不进入暂停，仍用 ROC 传输；计数 `ItlwmAwdlPauseSkips`。
- 进入和退出的其他步骤不变。

## 测试

- 25 个离线测试套件全部通过：
  - 源码检查确认暂停的进入和退出步骤里已经没有速率控制命令；
  - 新增单元测试检查频宽规则（80 MHz 及以下才暂停）和 40 MHz 配对（149/157 为下边）。
- 编译没有警告，没有新增导入符号。
